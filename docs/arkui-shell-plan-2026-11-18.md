# ArkUI 外壳方案（Qt 窗口不可用时的交付形态）

## 目标

在 Qt 窗口无法于本运行时启动的前提下，用 ArkUI 复刻 ChimeraX 的**外观骨架**，
让"打开即见原版界面"这件事在当前设备上成立：

- 顶部菜单栏：File / Tools / Actions / Presets / Help（文字与顺序同原版）
- 工具栏：Open、Save、Rotate、Translate、Zoom、Center、Undo、Redo（图标沿用 ChimeraX 资源）
- 左侧工具面板占位区（可用时接 ChimeraX 的 tool 面板）
- 中央 3D 视口：现有 EGL/GLES 表面（已跑通 GLSL 绘制）
- 底部命令栏：输入 ChimeraX 命令（已打通 `run` 通道）
- 底部状态栏：模型数 / 原子数 / 帧率 / 运行时状态

## 与"原版一致"的边界（必须说明）

| 维度 | 复刻程度 |
|---|---|
| 图标 | 用上游 `ChimeraX-icon512.png` 及工具图标资源，**一致** |
| 菜单/工具栏文字与顺序 | **一致** |
| 配色（深蓝底 + 浅色文字） | **一致** |
| 窗口整体布局（菜单/工具/视口/命令栏/状态栏） | **一致** |
| 控件级行为（Qt 的 dock 拖拽、面板浮动、快捷键表） | **不同**，ArkUI 需逐项实现 |
| Qt 特有能力（如 QGraphicsView 的交互细节） | **不同** |

结论：**外观 1:1 可做，交互细节需要逐项移植**；这不是 Qt 已经跑通的替代品，而是当前唯一能上的界面形态。

## 实现顺序（每步都可验收）

1. 静态骨架：菜单栏 + 工具栏 + 视口 + 命令栏 + 状态栏（截图验收）
2. 命令栏接 `runChimeraCommand`，回显进状态区
3. 工具栏按钮接真实动作（Open 走已打通的 PDB 读取器）
4. 视口把 `View.image_rgba()` 的结果贴到 XComponent（渲染通路已就绪，差像素搬运）
5. 工具面板：按 bundle 矩阵里的纯 Python 面板逐步接

## 现状

第 1、2 步所需能力全部具备（命令通道、图标资源、GL 表面），可立即开工。
