# 2026-11-18：真实 PDB 文件在应用内被 C++ 读取器打开

## 当前结论

**应用内通过 `chimerax.pdb.pdb.open_pdb` 读取一个真实 PDB 文件，读回 `models=1|atoms=4|residues=1`。设备断言 24/24。**

这打通了"文件 → 结构模型"的完整链路：`open_input`（解压/编码层）→ `open_pdb` →
`_pdbio`（C++ 解析）→ `atomstruct`（模型对象）→ `session.models`。

## 踩坑记录（都是真报错）

| 现象 | 原因 | 处理 |
|---|---|---|
| `'Session' object is not iterable` | `open_input(source, encoding)` 签名被误用成 `open_input(session, path)`，把 session 当路径返回了 | 改成 `open_input(path)` 取流，再交给 `open_pdb` |
| `'list' object has no attribute 'name'` | `open_db` 返回嵌套列表 | 展平后按 `num_atoms` 属性筛模型 |
| `'NoneType' object has no attribute 'register_available_commands'` | 走命令系统 `run(session, "open ...")` 需要 `session.toolshed`，dev 探针里的 session 没有 | 直接调用读取器函数（应用内引导已建 toolshed，将来命令路径可用） |

## 应用侧实现

页面新增 `OPEN_SCRIPT`：在应用沙箱写一个 4 原子 PDB → `open_input` + `open_pdb` → 输出
`models=…|atoms=…|residues=…`，节点 id `cx-open`，检查器断言前缀 `models=1|atoms=4|residues=1`。
