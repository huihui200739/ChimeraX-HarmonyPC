## 0. 一句话结论

`qtshim` 本来就是 **PyQt6 → PySide6 → PyQt5 → PySide2** 的探测顺序，`PyQt6` 在 OHOS 上不存在，所以**不需要改选择逻辑**就有 PySide6 分支；真正会让"起窗口"当场炸掉的是三件小事，本轮全部处理：

1. `promote_enums_pyside()` 里 `from enum import EnumType` 在 **CPython 3.11** 不存在（3.12 才加）→ `Qt.QtCore` 一 import 就 `ImportError`；
2. `qt_have_web_engine()` 在 OHOS 上每次都去 `import PySide6.QtWebEngineWidgets`（我们没编译 WebEngine）→ 每次都抛异常、stderr 有噪声；
3. `QT_QPA_PLATFORM=ohos` 与 `QT_PLUGIN_PATH`（`platforms/libqohos.so`）必须**在第一个 QGuiApplication 构造前**进环境，而 ChimeraX 的入口在 `ui.gui.UI` 里直接 `QApplication.__init__`，中间没有可插的位置。

补丁把 1/2/3 收到 `qtshim` 里（应用代码零改动），并给出 `Qt/ohos.py` 这一个显式的 OHOS 适配点。

## 1. shim 是怎么选绑定的（读上游结论）

- `prereqs/qtshim/Qt/__init__.py`：四个 `try/except ImportError` 级联，`using_qt6` 只被 PyQt6/PySide6 置 True；`Qt/QtWidgets.py`、`Qt/QtGui.py`、`Qt/QtCore.py`、`Qt/QtNetwork.py` 各自按 `using_*` 转发到对应绑定。
- 最小入口：应用侧只需要 `from Qt.QtWidgets import QApplication`（`src/bundles/ui/src/gui.py:29`）+ `from Qt.QtCore import ...`；`UI(QApplication)` 在 `gui.py:122` 里 `QApplication.__init__(self, [ad.appname])`。**Qt 绑定在 import 期就定型**，所以 OHOS 环境变量必须在 `import Qt`（也就是 `import chimerax.ui`）时设置 —— 这就是补丁把 `apply_platform_defaults()` 放在 `Qt/__init__.py` 顶部的原因。
- `qt_have_web_engine()` 的调用点（补丁要保证它们安全）：
  - `src/bundles/ui/src/gui.py:109`（`QtCoreApplication` 创建**之前**，会 `import Qt.QtWebEngineWidgets`）
  - `src/bundles/ui/src/gui.py:645`（主窗口 rapid access / `FileHistory` 缩略图）
  - `src/bundles/ui/src/widgets/__init__.py:17`（决定是否 `from .htmlview import HtmlView`）
  - `src/bundles/scheme_mgr/src/manager.py:47`（无 WebEngine 时走非 HTML 分支）
- 注意：任务描述里的 `src/prereqs/qtshim/` **不存在**；实际路径是 `prereqs/qtshim/`（与 `src/prereqs/{PyQt,Python,…}` 同级）。

## 2. 补丁做了什么（`0004-qt-ohos-pyside6-shim.patch`，5 个 hunk）

`git apply --check -v` 对上游树 **exit=0**，三个文件全部 "Checking patch …" 通过；已在 `/tmp` 的一次性副本上实跑 `git apply` + import 冒烟（见 §5）。

| # | 文件 / 位置 | 意图 |
|---|---|---|
| 1 | `Qt/__init__.py` `@@ -40,27 +40,53 @@` | 顶部 `import os, sys` + `from .ohos import …` 并**立刻** `_apply_platform_defaults()`：把 `QT_QPA_PLATFORM=ohos`、`QT_PLUGIN_PATH`、`QT_QPA_PLATFORM_PLUGIN_PATH` 在任何一个绑定/`QGuiApplication` 之前写进 `os.environ`。同一 hunk 把四个绑定的探测改成**记录失败原因**（`_binding_import_errors`），四者全失败时 `raise ImportError` 并列出每个绑定各自的原因——否则后面只是 "cannot import name QApplication"，会把"shiboken6 没部署"这种真因藏起来。 |
| 2 | `Qt/__init__.py` `@@ -128,6 +154,10 @@` | `qt_have_web_engine()` 先问 `_web_engine_enabled()`：OHOS 上直接 `return False`，**不再** `import Qt.QtWebEngineWidgets`（协议就是"False 且不抛异常"，也不污染 stderr）。`CHIMERAX_QT_NO_WEBENGINE=0/1` 可强制覆盖。 |
| 3 | `Qt/ohos.py`（新文件，193 行） | 唯一 OHOS 适配点：`is_ohos()`（`sys.platform == 'linux-ohos'`，`aarch64-linux-ohos` 三元组，可用 `CHIMERAX_QT_PLATFORM=ohos|none` 覆盖）→ `find_plugin_root()`（按 `CHIMERAX_QT_PLUGIN_ROOT` → `LD_LIBRARY_PATH` → `QT_PLUGIN_PATH` → `<site-packages>/lib` → `<app>/libs` → cwd 找含 `platforms/libqohos.so` 的目录）→ `apply_platform_defaults()`（幂等、**不覆盖**用户已设的值）→ `web_engine_enabled()` → `deployment_report()`（设备上可直接打印给报告）。 |
| 4 | `Qt/promote_enums.py` `@@ -23,7 +23,12 @@` | `from enum import EnumType` 加 `try/except ImportError: from enum import EnumMeta as EnumType`：**CPython 3.11 上这是必走的分支**，否则 `Qt.QtCore` 导入即 `ImportError`，整个 UI 层起不来。 |
| 5 | `Qt/promote_enums.py` `@@ -32,7 +37,13 @@` | `promote_enums_pyside()` 内逐个 `setattr(klass, name, value)` 包 `try/except (AttributeError, TypeError)`：shiboken 包装类型不保证可写，某个枚举别名写不进去时**不能**让整个 `import Qt` 失败。 |

`Qt/ohos.py` 只在 OHOS 上动手；在 macOS / Linux 上 `is_ohos()` 为 False，`apply_platform_defaults()` 立即返回，`QT_QPA_PLATFORM` 保持 `None`（已用宿主 smoke 验证，见 §5-A）。

## 3. 部署脚本 `tools/stage_qtshim_harmony.py`

按 `build/qtbind/out/deploy-manifest.json`（`deploy-manifest.txt` 的机器可读版）落盘，**默认 dry-run**，只有 `--apply` 才写：

```bash
# 只看计划（默认）——不动磁盘
python3 tools/stage_qtshim_harmony.py

# 真写（会写 build/chimerax-python/ 与 build/qt-deploy/libs/）
python3 tools/stage_qtshim_harmony.py --apply

# 演练到一次性根目录（本轮验证用的就是这条）
python3 tools/stage_qtshim_harmony.py --apply \
    --python-root /tmp/qtstage/python --libs-root /tmp/qtstage/libs
```

目录分工（默认值）：

| 目标 | 内容 | 条目数（dry-run 实测） |
|---|---|---|
| `build/chimerax-python/`（Python 包侧） | `PySide6/`（`.py` + `Qt*.abi3.so`）、`shiboken6/`（+ 包内 `libshiboken6`）、`Qt/`（**由补丁生成**，非直接拷上游） | python-ext 6 + python 18 + shim 10 |
| `build/qt-deploy/libs/`（原生侧） | `libQt6{CORE,Gui,Widgets,Network,OpenGL,OpenGLWidgets,PrintSupport,Sql,Xml,Concurrent,Test}.so`、`libqohos.so` + `platforms/libqohos.so`、`libc++_shared.so`、`libpyside6.abi3.so.6.12`、`libshiboken6.abi3.so.6.12` | native 17 |

脚本填了三处 manifest 缺口（`gaps`）：

1. **`shiboken6` Python 包整包**（manifest 只列了 `libs/arm64-v8a/libshiboken6.abi3.so.6.12`）。`PySide6/__init__.py` 第 66 行 `from shiboken6 import Shiboken`，没有这个包，`import PySide6` 直接失败 → 任何 Qt 模块都加载不了。这是清单最大的实质缺口。
2. **`shiboken6/libshiboken6.abi3.so.6.12` 再放一份**：`shiboken6/Shiboken.abi3.so` 的 RUNPATH 是 `$ORIGIN/`，运行时库必须与它同目录。
3. **`<python-root>/lib -> ../qt-deploy/libs` 符号链接**：所有交叉编译出的 `*.abi3.so` RUNPATH 是 `$ORIGIN/../lib`，而包在 `<python-root>/PySide6/`，因此 `<python-root>/lib` 必须存在并指向原生库目录。

另外脚本会把 `Qt/` 包**从上游树 + 补丁**生成到 `<python-root>/Qt`（在暂存区 `git apply`，上游树保持干净）。若目标目录里 `ohos.py` 已存在，则视为"已打过补丁"，直接拷贝。`--no-qtshim` 可只做 Qt/PySide6。

`--json-out` 输出完整计划 + ELF 闭包（本轮已生成 `reports/qtshim-2026-11-18.stage-plan.json`）。脚本还会列出 **hand-off**：15 个 `.so` 仍需 `app/` 打包线复制到 `app/entry/libs/arm64-v8a`（该目录属主线，本轮不碰）。

## 4. 离线可行性：部署集合的 NEEDED 闭包

用 `llvm-readelf -d`（SDK 内 `native/llvm/bin/llvm-readelf`）对**部署集合里全部 22 个 ELF** 逐库取 `NEEDED`/`RUNPATH`，然后按「部署集合 SONAME → `<python-root>/PySide6` → `<python-root>/shiboken6` → `<python-root>/lib` → `app/entry/libs/arm64-v8a` → API24 sysroot → SDK clang runtime」顺序解析：

```
ELF closure via .../native/llvm/bin/llvm-readelf: 22 lib(s) checked, 0 unresolved
  NEEDED closure: COMPLETE (every dependency resolvable inside the staged set / sysroot)
```

- 依赖命中分布：`sdk-sysroot` 88 次、`staged-set`（部署集合内部互相满足）74 次、`app-libs` 7 次（`libpython3.11.so.1.0` 只有应用私有 CPython 提供，已存在于 `app/entry/libs/arm64-v8a`）。
- `libqohos.so` 的 24 个 NEEDED：20 个来自 sysroot（`libace_napi.z`、`libace_ndk.z`、`libnative_window(_manager)`、`libnative_display_manager`、`libohinput`、`libohinputmethod`、`libpasteboard`、`libudmf`、`libohfileshare`、`libohhicollie`、`libpixelmap`、`libqos`、`libnative_vsync`、`libhilog_ndk.z`、`libhiappevent_ndk.z`、`libohfileuri`、`libEGL`、`libGLESv3`、`libc`），3 个落在部署集合（`libQt6OpenGL`/`libQt6Gui`/`libQt6Core`），1 个 `libc++_shared.so` 由我们随包携带（sysroot 里没有，必须从 SDK clang runtime 复制）。
- `libc++_shared.so` 只有 `libc.so` 一个 NEEDED，闭环。

**RUNPATH 层面仍有 3 个"运行时才暴露"的坑**（闭包能过、路径不对就崩，已写进报告 `elf_closure.runpath_risks`）：

| 库 | 现状 RUNPATH | 后果 | 处理 |
|---|---|---|---|
| Qt 预编译 `libQt6*.so`、`libqohos.so` | `/usr/local/Qt-6.12.0/lib` | 设备上不存在该路径 | 起进程时 `LD_LIBRARY_PATH=<libs root>`；如需彻底固化可 `patchelf --set-rpath '$ORIGIN'`（本轮**保持预编译包原样**） |
| `PySide6/*.abi3.so`、`libpyside6.abi3.so.6.12` | `$ORIGIN/../lib` | 需要 `<python-root>/lib` | 部署脚本建符号链接（见 §3-3） |
| `shiboken6/Shiboken.abi3.so` | `$ORIGIN/` | 需要同目录有 `libshiboken6.abi3.so.6.12` | 部署脚本复制一份进包 |

## 6. 窗口起来需要哪些环境变量

设备上（由主线在 `app/` 侧设，或在启动脚本里 export；shim 会在缺失时补默认值）：

| 变量 | 值 | 作用 |
|---|---|---|
| `QT_QPA_PLATFORM` | `ohos` | 选 QPA 插件（shim 在 OHOS 上自动补） |
| `QT_PLUGIN_PATH` | `<libs root>`（含 `platforms/libqohos.so`） | Qt 插件根（shim 自动探测并补） |
| `QT_QPA_PLATFORM_PLUGIN_PATH` | `<libs root>/platforms` | 直指 QPA 插件目录（shim 自动补） |
| `CHIMERAX_QT_PLUGIN_ROOT` | `<libs root>` | 显式指定插件根（优先于自动探测） |
| `LD_LIBRARY_PATH` | `<libs root>:<python-root>:<python-root>/PySide6` | 解决 Qt 预编译 `RUNPATH=/usr/local/Qt-6.12.0/lib` |
| `PYTHONPATH` | `<python-root>`（或等价 site-packages） | 找到 `PySide6`/`shiboken6`/`Qt`/`chimerax` |
| `PYOPENGL_PLATFORM` | `egl` | 沿用已有 EGL/GLES 通路（`chimerax.graphics.opengl`） |
| `CHIMERAX_QT_NO_WEBENGINE` | 可选 `1` | 强制 WebEngine 关闭（默认 OHOS 已关闭） |
| `CHIMERAX_QT_OHOS_DEBUG` | 可选 `1` | 把 shim 的决策打到 stderr（设备排障用） |

> 一句提醒：`Qt/ohos.py` 的探测是在 `import Qt` 时执行的；只要 `chimerax.ui` 在 `QApplication` 之前被导入（现状如此），环境变量就来得及。
