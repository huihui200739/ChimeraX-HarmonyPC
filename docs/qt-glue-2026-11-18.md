# Qt ↔ ArkUI 胶水：5 个最可能失败的点与判定日志

日期：2026-11-18 · 范围：`libqohos.so`（Qt 6.12.0 官方 OHOS 预编译）+ ArkTS Ability + `libchimeraxqt.so`
配套产物：`snippets/qt-ohos/`（ArkTS 三件套、`MainWindowNativeNode` 页、`qt_launcher.cpp`、CMake 片段）

判据来源全部是实读源码，不是推测。行号对应
`build/qt/src/qtbase/src/plugins/platforms/ohos/`。

**统一前置**：设 `hilog` 过滤，否则什么都看不到。

```bash
# 主机侧（无需 hdc 也能扫历史日志，设备验证归主线）
hdc shell hilog -Q pidoff; hdc shell hilog -b D -T ChimeraX -T ChimeraXQt -T ohosQtTemplate
# 关键字汇总（一眼定性）
hdc shell hilog | grep -E "CXQT_|CX_QT_|QPA|qpa|XComponent|dlopen|libc\+\+_shared|no Qt platform"
```

`qohosjsmain.cpp` 里的调试行只有在 Qt 开了 `QT_LOGGING_RULES` / debug 构建时才出。要拿到
`setupQtApplication() - sharedLibraryName:` 这类 `qOhosPrintfDebug` 输出，需要：

```bash
# 预编译包是 release, qOhosPrintfDebug 可能被编译掉; 用 hilog 里的 fatal/warning 兜底
hdc shell hilog | grep -E "qohos|Qt:" | tail -80
```

## F1 · libqohos.so 没被当 napi 模块加载 / XComponent id 对不上

**为什么最可能**：`import qpa from 'libqohos.so'` 要求 `.so` 落在 `libs/arm64/` 且 napi
`nm_modname` 是 `qohos`；XComponent 的 `libraryname` 必须写 `'qohos'`（`qohosjsmain.cpp:1928`），
id 必须是 `__nnMainWindow_<qAbilityInstanceId>`（`render/qxcomponent.cpp:57`），Registry 对
重复 id 直接 abort、对 `RenderXComponent_` 前缀拒绝（`qarkui/qxcomponentregistry.cpp:66-96`）。

**判定日志（出现即命中）**

| 日志 | 含义 |
|---|---|
| `Failed to retrieve id from xcomponent. Ignoring the component` | `OH_NativeXComponent_GetXComponentId` 拿不到 id（`qxcomponentregistry.cpp:52`） |
| `Ignoring xComponent due to unrecognized id value: <id>` | id 前缀不是 `__nnMainWindow_`/`__nnSubWindow_`/`__nnFloatWindow_`（`:62`） |
| `Ignoring xComponent because its id type is not supported in registry. id: RenderXComponent_...` | 用了 `XComponentType.SURFACE`（`:79`） |
| `Error: Duplicate xComponent detected. Duplicate ID: ...` | 页面被加载两次（`loadContent` 重复或 hot start） |
| ArkTS `TypeError: ... is not a function`（`qpa.setupQtApplication`） | `.so` 没部署到 `libs/arm64/`，或 `@types/libqohos.so` 没声明 |
| 屏上出现 `Qt window stage not provided by libqohos.so` | 页面起来了但 LocalStorage 没有 `createInfo` → 没走 `qpa.handleAbilityOnWindowStageCreate` |

**快速排查命令**

```bash
# 1) 设备上 .so 是否到位、导出符号是否是 napi 入口
hdc shell "ls -l /data/storage/el1/bundle/libs/arm64 | grep -E 'libqohos|libQt6|libc\+\+_shared'"
# 2) 主机侧直接看 .so 的模块名证据（nm_modname 是字符串常量 'qohos'）
strings build/qt/prebuilt/harmonyos-arm64/plugins/platforms/libqohos.so | grep -x qohos
# 3) 页面路径与 XComponent 三要素自检
grep -n "libraryname" app/entry/src/main/ets/pages/MainWindowNativeNode.ets   # 必须是 'qohos'
grep -n "XComponentType" app/entry/src/main/ets/pages/MainWindowNativeNode.ets # 必须是 NODE
grep -rn "pages/MainWindowNativeNode" app/entry/src/main/resources/base/profile/main_pages.json
# 4) Ability 是否真的转交了（而不是自己 loadContent）
grep -n "handleAbilityOnWindowStageCreate\|loadContent" app/entry/src/main/ets/entryability/EntryAbility.ets
```

**修法**：`libraryname: 'qohos'`；`type: XComponentType.NODE`；页面名固定；Ability 里删掉
`stage.loadContent(...)`。

## F2 · 找不到 platform plugin（Qt 起来了但 QApplication 构造失败）

**为什么最可能**：`QT_QPA_PLATFORM_PLUGIN_PATH` 与 `QT_PLUGIN_PATH` 都被 Qt 设成
*应用库目录本身*（`qohosjsmain.cpp:1699,1703`），而 QPA 按 `<pluginPath>/platforms/libqohos.so`
去找。也就是说设备上 `libs/arm64/libqohos.so` 必须**同时**扮演插件（靠这条路径）和 napi 模块。
`plugins/platforms/libqohos.so` 如果被放成 `libs/arm64/platforms/libqohos.so`，napi 加载就找不到。

**判定日志**

```
qt.qpa.plugin: Could not find the Qt platform plugin "ohos" in ""
This application failed to start because no Qt platform plugin could be initialized.
Reinstalling the application may fix this problem.
```
或 Python 侧 traceback 里出现 `QApplication` 构造处的 `Aborted` / `SIGABRT`。

**快速排查命令**

```bash
hdc shell "ls -l /data/storage/el1/bundle/libs/arm64/libqohos.so"
hdc shell "hilog | grep -iE 'qpa|platform plugin|QFactoryLoader'"
# 主机侧确认这个 .so 同时是插件又是 napi 模块
ls -la build/qt/prebuilt/harmonyos-arm64/plugins/platforms/libqohos.so   # 唯一一份
llvm-readelf -d build/qt/prebuilt/harmonyos-arm64/plugins/platforms/libqohos.so | grep -E 'NEEDED|RUNPATH'
```

**修法**：`libqohos.so` 平铺进 `libs/arm64/`，不要建 `platforms/` 子目录；`QT_PLUGIN_PATH` 不要
在 ArkTS/launcher 侧覆盖。

## F3 · dlopen 应用 .so 失败 / 找不到 `main`

**为什么最可能**：`appName` 拼出的路径是 `<bundleCodeDir>/libs/arm64/<appName>`
（`qohosjsmain.cpp:1683, 288`），拼错一个字符就 abort；`dlsym("main")` 拿不到也同样 abort
（`:295-300`）。另外 `libc++_shared.so` 缺失会在这之前以 NEEDED 解析失败出现。

**判定日志**

```
dlopen() failed to open library '<path>': <dlerror>
dlsym() failed to find 'main' symbol in library '<path>': <dlerror>
dlopen failed: library "libc++_shared.so" not found
dlopen failed: library "libQt6Core.so" not found
```
（前两条是 `qOhosReportFatalErrorAndAbort`，伴随 `Aborted` / 进程重启。）

**快速排查命令**

```bash
# 应用库与 appName 是否逐字一致
grep -n "APP_LIBRARY_NAME" app/entry/src/main/ets/qabilitystage/QAbilityStage.ets
ls -l app/entry/libs/arm64-v8a/ | grep -E "chimeraxqt|libc\+\+_shared"
# 导出符号（ELF 目标文件/共享库都适用；macOS 的 nm 读不了 ELF，用 DevEco 的 llvm-nm）
/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/native/llvm/bin/llvm-nm \
  --defined-only --dynamic app/entry/libs/arm64-v8a/libchimeraxqt.so | grep -w main
# NEEDED 全量对账（缺哪个补哪个）
/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony/native/llvm/bin/llvm-readelf \
  -d app/entry/libs/arm64-v8a/libchimeraxqt.so | grep NEEDED
```

**修法**：`APP_LIBRARY_NAME` = 实际文件名（含 `lib` 前缀与 `.so`）；`libc++_shared.so` 从 SDK
拷进 `libs/arm64-v8a/`；`main` 用 `extern "C" __attribute__((visibility("default")))` 并
不要开 `-fvisibility=hidden`。

## F4 · SDK/设备类型闸门 abort（连 main 都进不去）

**为什么最可能**：`setupQtApplicationImpl` 在建线程之前就做三道闸：
API < 23 abort（`qohosjsmain.cpp:1656`）、设备类型不在 `2in1/tablet/phone` abort（`:1662`）、
设备不受支持且未开逃生阀 abort（`:1672`）。本工程 `compatibleSdkVersion 6.1.1(24)` 满足 API，
但 `2in1` 之外的 PC/平板形态（例如设备上报 `default`）会直接命中第三条。

**判定日志**

```
setupQtApplicationImpl: unsupported OHOS version! Current API version: %d, minimum supported version: 23. Aborting.
setupQtApplicationImpl: Unrecognized device type: %s. Qt does not support unrecognized devices. Aborting.
setupQtApplicationImpl: Unsupported device type: %s. Aborting.
```

**快速排查命令**

```bash
hdc shell "param get const.ohos.apiversion"          # 期望 >= 23
hdc shell "param get const.product.devicetype"       # 期望 2in1 / tablet / phone
grep -n "deviceTypes" app/entry/src/main/module.json5
```

**修法**：`module.json5` 的 `deviceTypes` 与设备上报值保持一致；确实需要放宽时，**在
`setupQtApplication` 之前**把 `QT_IO_EXPERIMENTAL_ALLOW_UNSUPPORTED_DEVICES=true` 塞进环境
（这一条只能靠一个自建 napi `.so` 提前 `setenv`，因为 `setupQtApplicationImpl` 跑在 ArkTS 线程里，
`setenv` 之后才读，来不及从 ArkTS 侧设）。逃生阀只解决第三条，前两条是硬 abort。

## F5 · XComponent 有了，但 surface/EGL 起不来（Qt 窗口空白 / ChimeraX GL 初始化失败）

**为什么最可能**：Node 型 XComponent 的 surface 由
`QQtEmbeddedWindowNode::onSurfaceEvent(SurfaceCreated, nativeWindow)` 交出
（`qarkui/qqtembeddedwindownode.h:23-37`），Qt 再据此建 `QOhosEGLPlatformContext`。
`onAttach` 没透传 → `handleStartedUiInstance` 不触发 → QWindow 永不创建；
surface 事件到了但 EGL `eglMakeCurrent` 失败 → 窗口全黑、`grab()` 全 0。

**判定日志**

| 日志 | 含义 |
|---|---|
| `XComponentId: __nnMainWindow_... onAppear` 有，但之后无任何窗口绘制 | `onAttach` 没接 → QWindow 未创建 |
| `onAppear` 都没有 | XComponent 没挂上（回到 F1） |
| `eglMakeCurrent`/`eglCreateContext` 失败、`QOhosEGLPlatformContext` 报错 | native window 已销毁或尺寸 0×0 |
| Python 侧 `OpenGL.error.Error: Attempt to retrieve context when no valid context` | `PYOPENGL_PLATFORM` 未设 `egl`，PyOpenGL 走了 GLX/CGL |
| ChimeraX 侧 `view.image_rgba()` 抛异常 / 全黑 | 应用在 QPA 之前自建了 EGL 表面（与 Qt 抢同一个 native window） |

**快速排查命令**

```bash
hdc shell "hilog | grep -iE 'egl|EGL|surface|nativewindow|XComponent' | tail -60"
grep -n "PYOPENGL_PLATFORM" snippets/qt-ohos/qt_launcher.cpp       # 必须是 egl
grep -n "onAttach" app/entry/src/main/ets/pages/MainWindowNativeNode.ets  # 必须透传 createInfo.onAttach
# 是否还存在"自建 EGL 表面"的旧路径在同进程跑（会和 Qt 抢 native window）
grep -rn "eglCreateWindowSurface\|OH_NativeXComponent_RegisterCallback" app/entry/src/main/cpp/gl_surface.cpp
```

**修法**：`createInfo.onAttach` 原样挂到 `XComponent().onAttach(...)`；xcomponent 宽高不要给 0
（用 `'100%'`）；Qt 模式下**不要**再注册 `OH_NativeXComponent_RegisterCallback` 自建表面；
`PYOPENGL_PLATFORM=egl` 在 `Py_Initialize` 之前设好。

## 汇总：一次启动应该看到的日志序列（正序）

```
CX_QT_ONCREATE want=...                     # EntryAbility.onCreate
CX_QT_SETUP start appName=libchimeraxqt.so  # QAbilityStage 首次 setup
CX_QT_WINDOWSTAGE_CREATE                    # Ability 转交
XComponentId: __nnMainWindow_... onAppear   # libqohos 自己 loadContent 后的页
CXQT_MAIN argc=6 filesDir=... libs=...      # 应用 .so 的 main 被 Qt 线程调用
CXQT_PY_RUN stage=probe runtime=...         # CPython 初始化 + 跑探针脚本
CXQT pyside6=6.12.0 qt=6.12.0
CXQT qpa_platform=ohos
CXQT window_shown
```

任一行缺失，按上面对应的 F 编号排查：缺 1-3 行 → F1/F4，缺 4-5 行 → F3，缺 6-8 行 → F5。
