# 2026-11-17：鸿蒙应用入口（HAP）内嵌私有 CPython

## 当前结论

**ChimeraX 的鸿蒙应用入口已在模拟器上跑通：HAP 安装启动后，应用沙箱内初始化私有 CPython 3.11.18，页面读出解释器版本，`math.sqrt(16)=4.0`、`_ctypes` 经 libffi 调 `libc.strlen=19`、`hashlib.sha256` 前 8 位 `2c1179ae`，设备断言 7/7 全部通过。**

这不是完整 ChimeraX（不含 Qt、`chimerax.*` 应用模块、科研数据），但是可安装、可启动、带真实 Python 运行时的应用壳，为后续接入应用模块提供了可用基线。

## 应用结构

```
app/
├── AppScope/app.json5                 bundle com.example.chimeraxharmony 0.1.0
├── entry/src/main/ets/entryability/   UIAbility，负责初始化/收尾
├── entry/src/main/ets/pages/Index.ets 释放运行环境 → 初始化 Python → 三项探针
├── entry/src/main/cpp/                N-API 模块 chimerax_native（链接私有 libpython）
├── entry/libs/arm64-v8a/              libpython3.11.so.1.0 + 54 个扩展模块
└── entry/src/main/resources/rawfile/  cx-runtime.zip（标准库与解释器数据）
```

工具：

- `tools/package_app_runtime.py`：把私有运行环境装进应用（libpython 与扩展进 `libs/arm64-v8a`，其余打 ZIP 进 rawfile）
- `tools/build_hap.py`：hvigor 不接受含中文的工程路径，因此在 ASCII 临时目录构建，产物回拷 `build/hap/`
- `tools/device_app_check.py`：安装、启动、抓 UI 树读回状态与三项探针

## 设备上解决的两个真实限制

1. **`@ohos.zlib` 只能解 ZIP**：原 tar.gz 报 `900003 The input source file is not in ZIP format`，改为打包 ZIP。
2. **应用数据目录里的 ELF 不能 `dlopen`**：解压到 `files/` 的扩展模块一律 `Error loading shared library ... No error information`。改为把 54 个扩展作为**应用原生库**打进 `libs/arm64-v8a`，并在初始化时把该目录插入 `sys.path`（同时移除 `lib-dynload` 条目），扩展即可正常导入。
