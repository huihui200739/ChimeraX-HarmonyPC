# ChimeraX 鸿蒙 PC 适配 —— 阶段总结（2026-11-22）

## 一句话结论

UCSF ChimeraX v1.11.1 的完整引擎（私有 CPython 3.11.18）已在 OpenHarmony 6.1.1 / API 24 /
aarch64 上运行，**包括 ChimeraX 自己的 OpenGL 渲染器**——它现在能在鸿蒙上画出带元素颜色的分子。

## 官方渲染器为什么曾经"画不出东西"——七连修

| # | 缺陷 | 现象 |
|---|---|---|
| 1 | `glAttachShader` 未委托 ctypes 门面 | 程序链接成功但没有着色器 → 0 个 uniform block |
| 2 | `vertex_colors` 用 float（alpha=1.0） | 被判为全透明，不透明绘制阶段被跳过 |
| 3 | `vendor/graphics/_cxgl_sigs.py` 从未打包 | 门面没有签名表 → 指针/数组参数抛 `ArgumentError` |
| 4 | 参数统一包 `c_int` | `c_long`/`c_void_p`/`LP_c_float` 全部失配 |
| 5 | 缓冲区/属性/统一变量走 PyOpenGL | 返回 0 → VBO/IBO 无效 → 绘制被跳过 |
| 6 | 渲染前未 `view.draw()`；FBO/纹理存储未委托 | 离屏目标不完整 → 黑帧 |
| 7 | `AtomsDrawing.colors` 未填充 | 结构永远白/黑（`vertex_colors` 不是原子球的颜色通道） |

第 7 条的修法：`atoms.colors = element_colors(...)` 之后必须 `model._update_graphics()`，
才会执行 `p.colors = atoms.colors`。

## 架构

```
ArkTS (ArkUI) ── napi ──> libchimerax_native.so (C++)
                              │
                              └─ 私有 CPython 3.11.18 → ChimeraX v1.11.1
                                    ├─ chimerax.core / commands / atomic / graphics
                                    ├─ 14 个 bundle C 扩展
                                    └─ ctypes GL 门面 (chimerax/graphics/_cxgl.py)
                                          └─ libGLESv3.so + libEGL.so
```

渲染帧回传路径：
`View.image_rgba()`（Python）→ base64 → ArkTS `Base64Helper` → `PixelMap`（R/B 通道校正）
→ `Image` 组件显示。

## 未完成（精确卡点）

1. **Qt 原生窗口**：运行时拒绝对 Qt 插件所需的 JS 表达式求值（`LocalStorage.makeNewLocalStorage()`），
   四条路径均有日志，见 `docs/qt-status-2026-11-18-final.md`
2. **`_surface` 真实三角化**：GLU 用桩，封盖几何为空；其余网格计算可用
3. **依赖 UI 部件的命令**（如 `mlp`）：无 GUI 最小会话缺少 UI 对象
4. **界面 1:1 收敛**：工具面板、命令补全等尚未逐项对齐原版
